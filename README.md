## 官方更新后启动很慢（1.5.2）

安装 `dist/PokeSurvivor-1.5.2.apk`，系统显示版本 2.5.2，直接覆盖旧版，存档保留。

**原因**：APK 自带一份官方游戏代码，只有和官网版本完全一致时才用。官网几乎每天都在更新，一更新自带的就对不上，每次启动都要从官网（GitHub Pages，国内很慢）重新下载约 500 KB 压缩后的游戏代码，外加样式和语言包。网速慢时 45 秒还没下完，就会被切到离线版；下次启动又从头下载，一直下不完。另外下载超过 20 秒时，还会误报“小地图等增强功能加载失败”，游戏也会在没有小地图等功能的情况下进入。

**改动**：
- 官网更新后，新版游戏代码**只下载一次**，存在手机里，以后启动直接用本地的（样式和中文语言包也一样）。内存优化补丁也会自动用到新版上。
- 第一次下载时屏幕下方会显示下载进度和网速，并有“先玩本地离线版”按钮。只要还在持续下载，就不会中途被切到离线版（最多等 4 分钟）。
- 如果被切到了离线版，离线版会在后台把官网的新版本下载好，下次进在线版就不用再等。
- “增强功能加载失败”改为等官方代码真正运行完再判断，不再误报。

**实测**（安卓模拟器，模拟国内网络：官网 8 KB/s，谷歌服务不通）：
- 第一次启动约 100 秒，期间显示下载进度，最后进入在线版。之前的版本会在 45 秒时切到离线版。
- 第二次启动约 20 秒就能进入在线版。

## 后期内存优化（1.5.0）

安装 `dist/PokeSurvivor-1.5.0.apk`，系统显示版本 2.5.0，直接覆盖旧版，存档保留。已同步官方最新版本（f9fe33f52c）。

**测量结果**：模拟 20～40 分钟的后期对局（无尽模式，同屏约 65 个敌人）。原版会把预加载过的宝可梦动画图全部保留在已解码状态，约 330～360 张，图片约 230 MB；受击闪白还会为每张动画图另外复制一张同样大小的白色剪影，画布约 115 MB。真正 30 秒内会被画到的只有约 140 张。

**改动**（打包时修改 APK 内置的官方版本，离线和在线两种模式都生效；官方更新后在线模式会先用未修改的新版，等重新打包再生效）：
- 生成敌人时，原版每 10 秒会预加载接下来 1 分钟内会出现的所有宝可梦，每种 7 套动画。现在只预加载“待机”和“行走”两套，攻击、受击等动画第一次用到时再加载，加载完成前显示待机动作。
- 动画图缓存会定期清理：超过 120 张时，30 秒没画过的图会被释放；新加载图片时也会清理，上限从 200 张改为 120 张。
- 受击闪白的剪影只保留最近 6 秒用过的，最多 40 张。
- 小地图的数据改为紧凑格式（每格 1 字节，按 64×64 区块存储），记录范围更大，占用更少；小地图每次刷新不再重新分配画布。
- 结果：同样的后期对局，图片约 230 MB 降到约 105 MB，画布约 115 MB 降到约 35 MB，JS 内存约 25 MB 降到约 20 MB。

## 对局中闪退：自动恢复和补发收益（1.4.9）

安装 `dist/PokeSurvivor-1.4.9.apk`，系统显示版本 2.4.9，直接覆盖旧版，存档保留。

**原因（推测）**：游戏运行在安卓的网页组件（WebView）里，网页部分是一个单独的进程。长时间对局内存占用较大，手机内存紧张时，系统会先杀掉这个网页进程（也可能是网页进程自己崩溃）。之前 APK 没有处理这种情况，安卓的规定是：不处理就连整个应用一起关闭，所以看起来就是“闪退”，这一局的收益也全部丢失。

**改动**：
- **不再直接闪退**：网页进程没了时，自动重新打开游戏。如果 20 秒内连续出现两次，就不再重启，避免反复重启。
- **自动补发这一局的收益**：对局中每 8 秒、以及切到后台时，记录一次这局已经获得的进度（坚持时间、击败数、首领数、拾取的金币）。正常结束的对局会清除这条记录。如果对局是被意外中断的，下次进入菜单时，会用游戏自己的结算公式补发金币，计入对局次数等统计，并弹出提示。抽取券官方本来就是捡到时立即保存的。坚持不到 30 秒的对局不补发；在线游客模式本来就不保存，也不补发；只补发给原来那个账号。
- **降低内存占用**：减少资源地图的缓存上限（地形记录 10 万 → 6 万格，预测缓存 10 万 → 4 万格）。

验证：新增 `node tools/test-run-rescue.cjs`：对局进行中强制重新加载（模拟闪退），重开后按公式补发 140 金币并计入 1 局、显示提示；正常结束的对局会清除记录，下次启动不会重复补发。53 项单元测试（新增：原生代码已处理网页进程丢失）及其余全部测试通过；原生代码已反编译核对。**真机上网页进程被杀的情况无法在电脑上复现，需要实际验证。**

点按钮后会出现可选的性格 / 特性 / 招式，点一个即可使用，道具会被消耗。

**修复**：官方点道具按钮后，选项出现在详情页最下面，而详情页同时跳回了顶部；手机上详情区域较小，看起来像“点了没反应”。现在点按钮后会自动滚动到选项处，并用金色边框提示一下。

**同版补充**：

- 有 153 只宝可梦只有一种特性（例如美录梅塔、耿鬼、梦幻），官方不会为它们显示特性胶囊 / 膏药按钮。现在持有这两种道具时，会在“特性”一行注明“只有一种特性，不能更换”。

- 使用特性胶囊 / 特性膏药时，每个可选特性下面会显示它的效果说明（官方原本只显示名字）。薄荷的选项本身已显示性格加减。
- 薄荷 / 特性胶囊 / 招式学习器按钮缩小成小标签（高约 19px），和“性格”“特性”文字放在同一行，不再单独占一行。

验证：新增 `node tools/test-item-picker.cjs`（在商店买特性膏药 → 皮卡丘详情页“特性”行出现按钮 → 点击后选项在可视范围内 → 选择“避雷针（隐藏特性）”后生效、膏药数量减为 0）。其余全部测试通过。

## 反复提示“有新版本”（1.4.6）

安装 `dist/PokeSurvivor-1.4.6.apk`，系统显示版本 2.4.6，直接覆盖旧版，存档保留。

**原因**：这是官方游戏自带的更新检查，不是我们 APK 的版本。官方游戏启动 30 秒后会读取服务器上的 `version.json`（每次都读最新的），和当前页面里的游戏版本对比，不一致就提示“有新版本，X 秒后更新”并刷新页面。但官网页面本身会被缓存 10 分钟（CDN 和 WebView 都会缓存）。官网一发新版本（这两天就更新了好几次，其中 10 月 21 日那次还是强制更新），刷新后拿到的往往还是缓存里的旧页面，于是一直提示、一直刷新，最长约 10 分钟，在战斗中还会被强制保存后重载。

**改动**：页面启动时由增强模块自己检查一次 `version.json`；发现页面已经过期，就换成带版本号的新地址（`/?fresh=新版本号`）重新打开一次，确保拿到服务器上的最新页面。每个新版本最多多刷新一次，不会循环。同时把 APK 内置的官方文件更新到当前版本 `9c81bc64df`。

验证：新增 `node tools/test-stale-page.cjs`，模拟缓存里的旧页面：只多加载一次就运行最新版本，官方更新检查不再提示。52 项单元测试及在线、离线、地图、阿尔宙斯、双摇杆测试通过。

## 启动等待时间过长（1.4.5）

安装 `dist/PokeSurvivor-1.4.5.apk`，系统显示版本 2.4.5，直接覆盖旧版，存档保留。

**原因**：
- 原来的 45 秒保护从“网页开始显示”时才计时。如果连官网服务器都连不上或极慢（国内访问官网所在的 GitHub Pages 时常出现），网页一直不开始显示，计时就不会启动，只能等 WebView 自己报连接超时，这可能要好几分钟。

- APK 内置当前版本的官方游戏代码、样式、语言加载器和语言包。官网请求的版本号（`?v=` 指纹）和 APK 内置的完全一致时，直接使用内置文件，不再下载；官网更新后版本号变化，自动改为从网络下载新版本，不会用旧代码冒充新版。

验证：52 项单元测试（新增：内置文件只在版本号一致时使用、25 秒启动计时已编入原生代码）及在线、离线、地图、阿尔宙斯、双摇杆测试通过；原生代码已反编译核对。连接卡住的情况无法在电脑上真实复现，需要用户实测。

**原因**：官网最近更新后，游戏代码和语言加载器用了较新的 JavaScript 写法（`??`、`?.`，需要 Chrome 80 以上）。系统 WebView 低于 Chrome 80 的手机（不少 vivo / OPPO / 小米旧机型、没有谷歌服务的系统）解析失败，游戏完全不启动，停在加载页。原来的 45 秒超时会切到离线版，但离线版用的是同一份官方代码，同样启动不了，又没有超时保护，于是一直加载。之前修的是网络加载超时，这次是新的兼容性问题。

**改动**：
- 离线版：打包时把官方游戏代码、语言加载器编译成旧 WebView 能识别的写法（保持压缩格式，官方代码有防改动自检，排版变化会卡死），并补上旧版缺少的函数。增强模块改为单独文件先加载，即使游戏代码出问题也能显示提示。
- 在线版：官方代码在旧 WebView 上无法运行时，几秒内直接切到离线版，不再等 45 秒；离线版里提示“系统 WebView 版本较旧（Chrome xx），在线版需要 Chrome 80 以上”，并说明更新“Android System WebView”后可以使用在线版和账号。
- 离线版 25 秒内没启动成功，会显示原因和 WebView 版本，提供“重新加载 / 返回在线版”，不会再无限加载。

验证：用 Chromium 69、79、83 实测——修复前 Chrome 79 离线版报语法错误、停在加载页；修复后 69 / 79 / 83 离线版都能进入（简体中文），Chrome 79 打开官网时 7 秒内自动转入离线版并显示提示，Chrome 83 正常在线。51 项单元测试（新增：打包文件按 ES2018 解析、加载器回退）及在线、离线、地图、阿尔宙斯、双摇杆测试通过。

**限制**：旧 WebView 只能玩离线版，无法登录官网账号；在线需要更新 WebView（官方游戏的要求，我们无法绕过）。

## 云存档及时同步（1.4.3）

**之前 30 分钟不出阿尔宙斯的原因**：旧版本地离线版使用的是阿尔宙斯更新之前的游戏代码，进入离线版（包括网络问题自动切换的离线版）时根本没有这个事件。现在离线版换成官网当前代码的快照（`source/vendor/official/`），并且已验证在线版与离线版第 30 分钟都会触发。

**挂梯子后没有汉化和小地图的原因**：官网会注册 Service Worker（`sw.js`）。一旦注册成功，Android WebView 中这个 Worker 发出的请求不再经过 APK 的拦截器，加载的是没有汉化与地图的原版脚本，而且之后每次启动都会这样。旧版用 Java 自己下载主脚本（与 WebView 网络栈分开，在梯子或慢速网络下更容易失败），失败时原版脚本会直接运行，从而注册这个 Worker。修复：
- 主脚本改由 WebView 自身下载（使用与页面相同的梯子/代理），APK 只注入一段很小的加载器。
- 新增 Service Worker 请求拦截，并用一个会自我注销的 `sw.js` 替换官网版本，清除官网缓存（只清除 `ps-code-*`/`ps-art-*` 缓存，存档不受影响）。已受影响的手机升级后再次打开即可恢复。

**资源地图恢复“直接全部显示”**：之前为了兼容官网新代码，地图被临时改成只显示走过的区域。现在按官网当前的地图生成规则（与官网完全相同的种子和常数）直接推算整张地图的地形和资源，打开就能看到全部；走过的地方显示为已确认，没走过的资源带虚线圈。推算是独立计算，不会改动游戏里的世界或影响联机同步。已验证 4 个种子、每个 4 万格的地形和全部资源与官网生成结果完全一致（`node tools/test-map-predict.cjs`）。装过之前 1.3.5 的设备会自动重新打开“显示预测资源”。

**结算框溢出屏幕**：部分手机的 WebView 不支持 `dvh` 单位，结算框高度没有被限制，居中后上下都超出屏幕。改为用实测的窗口高度限制，内容再多也只会变成可滚动，不会被截掉；横屏手机上的结算统计改为四列紧凑排列。另把结算里没翻译的 “recogidas” 译为“拾取”。

**国内不挂梯子不能登录**：官网账号用的是 Google Firebase（`identitytoolkit.googleapis.com`、`firestore.googleapis.com` 等），国内网络无法直连。这一点无法只靠修改 APK 解决；需要使用梯子，或另外搭建一个国内能访问的中转服务器。国内用户请在使用梯子的情况下登录，现在开着梯子也能看到汉化和小地图。不登录时可以用“本地离线存档”游玩。

验证：`node tools/test-online.cjs`（真实官网，含无尽模式过 30 分钟不触发、阿尔宙斯模式第 30 分钟触发、`sw.js` 替换）、`node tools/test-offline-startup.cjs`、45 项单元测试、APK 签名/对齐/资源表检查，并反汇编确认 DEX 中的 Service Worker 拦截。另用浏览器复现了“Worker 注册后页面拦截器收不到主脚本请求”。**尚未在 Android 真机上验证**，也没有在国内网络或梯子环境实测，请朋友安装后反馈。

## 继续修改与重新打包

网页源码位于 `source/`。编辑 `source/dev.html` 和各模块，运行：

```powershell
node tools/build-local.cjs
node --test tests/world.test.cjs tests/translation.test.cjs tests/apk-compat.test.cjs tests/cloud.test.cjs tests/cutout.test.cjs tests/audio-lifecycle.test.cjs
node tools/build-online.cjs
node tools/test-online.cjs
node tools/browser-check.cjs
powershell -NoProfile -ExecutionPolicy Bypass -File tools/package-apk.ps1
```

`build-local.cjs` 使用本地 Node 构建，无须联网安装依赖。浏览器验证脚本使用相邻 `PokeSurvivor_ChineseWideMap/.research/node_modules/playwright` 与本机 Edge。

`package-apk.ps1` 使用本项目 `tools/jre/` 中的便携 Java 和 `tools/uber-apk-signer.jar`。运行环境来自 Eclipse Adoptium 官方发布，签名工具来自 patrickfav/uber-apk-signer 官方发布，下载后已核对 SHA256。工具发布信息和校验值保留在 `tools/`。

本地签名密钥为 `signing/widemap.p12`（alias `widemap`，本地构建密码 `android`）。保留该文件，后续用相同密钥签名才能覆盖安装此修改版并保留其数据。此密钥不属于原作者。

`tools/integrate.cjs` 是首次移植的记录脚本，不要对已修改的 `source/` 重复运行。`tools/map-labels.cjs` 维护新增地图菜单的中英译文。原作者的 `source/tools/build.js` 保留作为原始资料，当前修改版请使用上述本地构建命令。

## 1.0.1 安装修复

首版 1.0 在重新创建 ZIP 时压缩了原包保持 STORED 的文件，导致 `resources.arsc` 被 DEFLATE 压缩。Android 安装器因此返回 `INSTALL_PARSE_FAILED_RESOURCES_ARSC_COMPRESSED (-124)`。首版的签名和 zipalign 校验无法发现“资源表已压缩”这项问题，不能视为可安装性的完整证明。

1.0.1 保留原 APK 所有 STORED 文件的存储方式，并在签名后通过独立 ZIP 结构检查强制验证：资源表压缩方法为 0、本地与中央目录方法一致、实际数据地址可被 4 整除、原包所有未压缩文件仍未压缩。打包脚本会在此检查失败时停止发布。

失败的首版只保存在 `verification/PokeSurvivor-ChineseMap-1.0-broken.apk`，用于回归测试。旧下载路径 `dist/PokeSurvivor-ChineseMap-1.0.apk` 如存在，是修复成品的兼容副本；建议直接使用 1.0.1 文件名。

官方要求见 https://developer.android.com/about/versions/11/behavior-changes-11#app-packaging 。修复后仍须由手机实际安装验证其他设备相关行为。
